# 打卡助手 · 微信小程序

一个原生微信小程序 + 云开发的每日打卡工具：添加想坚持的小事、每天点一下打卡、到点通过微信「服务通知」提醒你。

- 前端：微信原生小程序（WXML / WXSS / JS），**免构建**，直接用微信开发者工具打开即可运行
- 后端：微信云开发（云数据库 + 云函数 + 定时触发器 + 订阅消息）

## 三、先跑起来（纯本地，2 分钟）

1. 打开**微信开发者工具** → 导入项目 → 选择本目录 `wechat-checkin`。
2. AppID 填你自己的小程序 AppID（没有就选「测试号」）。
3. 直接编译运行。此时小程序已经是完整可用的本地打卡工具（首次启动会写入 4 个示例打卡项），
   只是**没有后台定时推送**——不配置云开发时，提醒只在打开小程序时以横幅形式提示。

> 想换掉示例数据：`我的 → 恢复示例打卡项` 可以重新写入，`清空所有数据` 可以全部清掉。

## 四、开启真正的定时提醒（完整流程）

### 1. 开通云开发

1. 开发者工具顶部点「云开发」→ 开通（选按量付费的免费额度即可）。
2. 复制**环境 ID**（形如 `release-1g9xxxxx`，在 云开发控制台 → 设置 → 环境 ID）。

### 2. 填写前端配置

打开 [`miniprogram/config.js`](miniprogram/config.js)：

```js
cloudEnv: 'release-1g9xxxxx',   // ← 填你的环境 ID
subscribeTemplateId: '',        // ← 下一步拿到模板 ID 后再填
enableCloud: true,
```

### 3. 申请订阅消息模板

1. 登录 [微信公众平台](https://mp.weixin.qq.com) → **功能 → 订阅消息 → 公共模板库**。
2. 搜索「打卡提醒」「待办提醒」之类的模板，选用一个包含以下字段的：
   - 打卡项目（`thing` 类型）
   - 提醒时间（`time` 类型）
   - 温馨提示 / 备注（`thing` 类型）
3. 选用后进入「我的模板」，复制**模板 ID**。
4. 把模板 ID 填进 `miniprogram/config.js` 的 `subscribeTemplateId`。

如果模板字段编号不是 `thing1 / time2 / thing3`，同步修改 `config.js` 里的 `templateFields`：

```js
templateFields: {
  title: 'thing1',   // 对应模板里的「打卡项目」
  time: 'time2',     // 对应「提醒时间」
  remark: 'thing3'   // 对应「温馨提示」
},
```

> 云函数发送时会按字段编号前缀自动做长度/格式兜底（`thing` ≤20 字、`phrase` ≤5 字等），
> 所以字段类型填错也不会把云函数搞崩，只会推送内容不完整。

### 4. 部署云函数

在开发者工具左侧资源管理器里，右键 `cloudfunctions/checkinApi` → **上传并部署：云端安装依赖**；
对 `cloudfunctions/checkinReminder` 做同样操作。

部署完成后，云函数目录上会出现云朵图标。

> `config.json` 里已经声明了 openapi 权限 `subscribeMessage.send` 和每分钟一次的定时触发器，
> 随部署一起生效，不需要手工去控制台加。

### 5. 建议调整（可选但推荐）

在**云开发控制台 → 云函数 → checkinReminder → 配置**里：

- **超时时间**：从默认 3 秒调到 **20 秒**（用户量上来后一次扫描更从容）。
- 想省额度的话，可以把定时触发器改成每 5 分钟一次（编辑 `cloudfunctions/checkinReminder/config.json`
  的 `config` 字段，cron 为 7 位 `秒 分 时 日 月 周 年`）：

  | 频率 | cron |
  | --- | --- |
  | 每分钟（默认，提醒最准） | `0 * * * * * *` |
  | 每 5 分钟 | `0 */5 * * * * *` |
  | 每 10 分钟 | `0 */10 * * * * *` |

  注意改成低频后，提醒时间会被对齐到最近的刻度（比如设 09:03 的提醒，每 5 分钟跑一次就只在 09:05 命中）。

### 6. 在小程序里开启提醒

1. 编译运行 → 进「我的」页面 → 点 **「开启微信提醒」**。
2. 弹窗里**务必勾选「总是保持以上选择」**，然后点允许。
3. 点 **「发送一条测试提醒」** 验证链路，应该马上在微信「服务通知」收到一条。

## 五、关于订阅消息的一个重要限制（必读）

微信的**一次性订阅消息**规则是「授权一次 → 只能推送一条」。
本项目的应对方式：

- 每次打开小程序（以及打卡、保存带提醒的打卡项时），会静默调用一次
  `wx.requestSubscribeMessage` 累积额度；
- 节流间隔默认 6 小时，可在 `config.js` 的 `autoSubscribeInterval` 调整；
- 用户勾选「总是保持以上选择」后，后续调用不再弹窗、直接累积，不会打扰用户；
- 一旦微信返回 `43101`（额度用完），云函数会把该用户标记为 `needResubscribe`，
  下次打开小程序首页会出现「提醒额度已用完，点此重新授权」的横幅。

**如果你需要「一次授权、长期推送」**，只能走**长期订阅消息**：需要在微信公众平台申请，
且仅对政务民生、医疗、金融、教育、交通、体育、居民服务等特定行业类目开放。
个人主体小程序通常拿不到，所以本项目的方案是业界通行的做法。

## 六、数据与隐私

- 打卡数据默认**只存在手机本地**（`wx.setStorageSync`），卸载小程序即丢失，请用导出功能备份。
- 开启云开发后，数据会同步到**你自己的**微信云环境：
  - 集合 `ck_users`：每个用户一条文档，存打卡项配置、推送状态、已推送标记
  - 集合 `ck_checkins`：每条打卡记录一条文档（`openid_planId_date` 作为 `_id`）
- 两个集合由云函数首次调用时**自动创建**，无需手工建表。
- 云函数只按 `openid` 读写自己的数据，其他人看不到。

| 12 | 配置好云开发后点「立即同步到云端」 | 提示同步成功，并显示「云端打卡项 N 个」 |
| 13 | 点「开启微信提醒」→ 勾选「总是保持以上选择」→ 允许 | 提示「提醒已开启」，标签变绿 |

第 15 步是整条链路的最终验证。如果没收到，依次看：
云函数日志有没有每分钟一条 `[checkinReminder]` → `sent` 是否为 0 → 订阅额度是否用完（43101）
→ `MINIPROGRAM_STATE` 是否与当前版本（开发/体验/正式）匹配。

## 八、常见问题

**Q：点「开启微信提醒」报错 `cloud function not found` / 云开发未就绪？**
A：`config.js` 里的 `cloudEnv` 没填，或者两个云函数还没「上传并部署」。「我的」页面会显示具体原因。

**Q：测试推送提示「订阅次数已用完」？**
A：重新点一次「开启微信提醒」，弹窗里勾选「总是保持以上选择」。

**Q：提醒时间不准？**
A：检查定时触发器是否是每分钟（`0 * * * * * *`），以及 `checkinReminder` 是否部署成功
（云开发控制台 → 云函数 → 日志，能看到每分钟一条 `[checkinReminder] {"at":"..."}`）。

**Q：收不到推送，但云函数日志显示 sent > 0？**
A：`checkinReminder/index.js` 顶部的 `MINIPROGRAM_STATE` 默认是 `formal`（正式版）。
在**开发版/体验版**调试时请改成 `developer` / `trial` 并重新部署，否则微信不会投递。

**Q：小程序里 TabBar 没有图标？**
A：为了保证零二进制资源、开箱即用，TabBar 只配了文字。想要图标的话，
往 `miniprogram/images/` 放 6 张 81×81 的 PNG，再在 `app.json` 的 `tabBar.list`
每一项里补上 `iconPath` / `selectedIconPath` 即可。

**Q：想加「补打卡」（给过去的日期打卡）？**
A：数据层已支持——`store.check(planId, '2026-02-10')` 传任意日期即可。
在 `pages/stats/stats.js` 的 `onCellTap` 里把 `wx.showModal` 换成含「补打卡」按钮的弹窗即可接上。

## 九、二次开发提示

- 所有业务读写都收敛在 [`miniprogram/utils/store.js`](miniprogram/utils/store.js)，
  页面只调用它的方法，换存储后端（比如改成直接读云数据库）只需改这一个文件。
- 重复规则的判定在**两处**保持一致：`miniprogram/utils/date.js` 的 `isActiveOn`
  和 `cloudfunctions/checkinReminder/index.js` 的 `isActiveOn`。改动时请同步。
- 云端用户文档结构见 `cloudfunctions/checkinApi/index.js` 的 `actionSync`。
